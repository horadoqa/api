🚀 Principais Termos em APIs

API Integration

É o processo de conectar diferentes sistemas ou aplicações por meio de APIs para troca de dados e automação.

Exemplo:
Um e-commerce integrado à API dos Correios para calcular frete automaticamente.

API Gateway

É uma camada intermediária que centraliza o gerenciamento das APIs, controlando autenticação, segurança, monitoramento e roteamento.

Exemplo:
Uma empresa usa um API Gateway para controlar acesso aos serviços de pagamento, usuários e pedidos em um único ponto.

API Lifecycle

Representa todo o ciclo de vida de uma API: planejamento, desenvolvimento, testes, publicação, monitoramento e descontinuação.

Exemplo:
Uma fintech cria uma API, publica documentação, monitora uso e depois lança uma nova versão.

Authorization

Define o que o usuário autenticado pode acessar ou executar.

Exemplo:
Um usuário comum pode visualizar pedidos, mas apenas administradores podem excluí-los.

        "nome": "Hora do QA",

        "administrador": "true"
      }

CRUD

Conjunto das quatro operações básicas em sistemas:

  • Create → Criar
  • Read → Ler
  • Update → Atualizar
  • Delete → Excluir

Exemplo:
Cadastro de clientes em um sistema.

Cache

Armazenamento temporário de dados para melhorar o desempenho e reduzir consultas repetidas.

Exemplo:
Salvar resultados de uma consulta de produtos mais acessados.

Tipos de cache

  • Client-side cache → Armazenamento no lado do cliente (ex: navegador).
  • Server-side cache → Armazenamento no servidor para acelerar respostas.
  • Distributed cache → Cache compartilhado entre múltiplos servidores.

Status do cache (x-cache)

  • MISS → A resposta não foi encontrada no cache e precisou ser obtida do servidor de origem.
  • HIT → A resposta foi encontrada no cache e retornada sem precisar gerar novamente no servidor.
  • BYPASS → A resposta foi obtida diretamente do servidor de origem devido a uma regra de bypass.
  • EXPIRED → O conteúdo armazenado expirou e foi atualizado pelo servidor de origem.
  • STALE → O conteúdo desatualizado foi retornado porque o servidor de origem não respondeu corretamente.
  • UPDATING → O conteúdo antigo ainda está sendo servido enquanto o cache é atualizado em segundo plano.
  • REVALIDATED → O conteúdo em cache foi validado junto ao servidor de origem usando requisições condicionais.

Client

Aplicação ou dispositivo que consome uma API.

Exemplo:
Um aplicativo mobile consumindo uma API de banco.

Method

Define a ação realizada na API.

  • GET → Buscar dados
  • POST → Criar dados
  • PUT → Atualizar dados
  • DELETE → Remover dados

Exemplo:

GET https://serverest.dev/usuarios

Pagination

Técnica usada para dividir grandes volumes de dados em páginas menores.

Exemplo:
Mostrar 20 produtos por página em um marketplace.

Payload

Conjunto de dados enviados em uma requisição ou resposta.

Exemplo:


      {
        "nome": "Hora do QA",
        "email": "horadoqa@qa.com.br",
        "password": "1q2w3e4r",
        "administrador": "true"
      }

Query Parameters

Parâmetros enviados na URL para filtrar ou modificar consultas.

Exemplo:


        GET https://serverest.dev/usuarios?administrador=true
        GET https://serverest.dev/produtos?nome=Logitech

Rate Limiting

Controle da quantidade de requisições permitidas em determinado período.

Exemplo:
Máximo de 100 requisições por minuto por usuário.

Quando o limite de requisições é excedido, a API retorna o código HTTP 429 (Too Many Requests).

Request

Requisição enviada pelo cliente para a API.

Exemplo:

GET https://serverest.dev/usuarios

Resource

Objeto ou entidade disponibilizada pela API.

  • /usuarios
  • /pedidos
  • /produtos

Response

Resposta retornada pela API após uma requisição.

Exemplo:


        {
          "message": "Cadastro realizado com sucesso",
          "_id": "jogfODIlXsqxNFS2"
        }

Response Code

Código HTTP que informa o resultado da operação.

  • 200 → Sucesso
  • 201 → Criado com sucesso
  • 400 → Requisição inválida
  • 401 → Não autenticado
  • 403 → Acesso negado
  • 404 → Não encontrado
  • 429 → Too Many Requests
  • 500 → Erro interno do servidor

Exemplo:
Ao criar um usuário corretamente, a API retorna 201 Created.

Ferramentas

Algumas ferramentas utilizadas para interagir com a API.

  • cURL - Ferramenta utilizada para realizar requisições HTTP via terminal, muito usada para testes rápidos de APIs e automações.
  • Postman - Plataforma popular para testar, documentar e automatizar APIs com uma interface intuitiva e suporte a coleções.
  • Insomnia - Cliente REST leve e moderno para testes de APIs REST e GraphQL, focado em produtividade e simplicidade.
  • Swagger - Ferramenta utilizada para criar, visualizar e documentar APIs seguindo a especificação OpenAPI.
  • Hoppscotch - Plataforma web leve e rápida para testar APIs REST, GraphQL e WebSocket diretamente no navegador.
